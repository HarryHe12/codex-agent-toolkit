测试日期：2026-11-21（Asia/Shanghai）

方法
1. 运行前定义三类正向任务、一个不应触发新流程的错字任务及独立验收条件。
2. 未加入新 skill 与加入第一版 skill 分别使用不同的独立 agent 会话与隔离 Git 仓库。模型配置继承同一主会话，未人为切换；运行器未提供可审计的精确模型快照、token 与费用数据。
3. 初始共 8 次执行，每个条件一次。审查者只接收 north/south 匿名产物、改动规模和验收标准，不知道条件或模型标签。主 agent 复核其发现并通过实际命令验证。
4. 修改后的三个正向 skill 各重新执行一次。重复的是已见过任务，属于修正验证，不是独立留出集。Panel 重跑使用初始文件快照，未保留完整 Git 历史；不能将其与初轮的差异全部归因于 skill。

独立观察
- 两个初版边界检查均正确处理原先 7 个直接、别名、相对、间接和合法依赖案例。
- 匿名审查提出检查对象为空时可能误报。实际复现：两者在没有 app 源码时均退出 0，并输出通过。
- 优化 skill 后生成的边界检查在 7 个原案例和新的空源码案例均符合预期。没有对动态运行时 import 给出正确性保证。
- 两版初始指南与优化版指南都能让正常 CLI 通过，并拒绝去掉 trim 的错误产品；失败证据仍然存在。复验器按指南的前提准备 evidence 目录，在临时 Git 仓库执行，不操作真实用户存储。
- 第一版 project-verification 增加了路由 skill、功能地图及相关审阅文件，未在这轮故障中取得额外检出收益。将路由和独立地图改为按需后，优化版仅保留原指南与证据，未再创建额外 skill 或地图。
- 两个初始效果判断均正确拒绝因果归因，但分别给出至少 160／36 次运行和未经业务论证的百分比门槛。优化后提出先少量配对诊断、按波动和风险扩样，未再发明固定门槛。
- 普通错字任务两种初始条件均只改目标单词，没有扩大为验证体系或仓库重构。优化版的触发描述没有改变，未再次执行此任务。
- 上次发布包有 4 处未打包的本地治理依赖链接。改为按能力使用目标环境治理后，独立分发检查通过。

改进与保留
- 保留独立业务预期、错误先失败再修复、真实操作及证据要求。
- 减少强制路由和地图，将错误扫描根目录、空覆盖和导入支持范围纳入约束验证。
- 将诊断规模与业务门槛分开；保留环境、版本、工具和成本记录，披露共享状态干扰。
- 原有全局 AGENTS、既有 hooks、门禁阈值与部署权限没有修改。

限制
这不是统计效果研究。没有足够重复或独立泛化集，不能声称总体成功率提高或速度提升。真实环境的共享 hook 曾阻塞其他候选收尾，部分候选没有执行会写仓库外状态的手动全局 hook；不能把其自报认证当证据。正式分发仓库另执行本地质量门禁与打包测试。
部分文件数包括治理证据，受本机治理流程影响。源文件的最新文本恢复了原有运行记录要求，这个语义保留修订仅做结构和逐条审阅，未为该一句话另开独立行为试验。
